# 집직구 실거래가 데이터 파이프라인

## 목표

국토교통부 실거래가를 그대로 보여주지 않고, 지도 좌표와 단지 상세 정보를 결합한 뒤 취소 거래를 제거해 신뢰 가능한 단지 단위 데이터로 제공한다.

## 처리 흐름

1. RTMS 실거래 수집
   - API: `국토교통부_아파트 매매 실거래가 자료` 또는 상세 자료
   - 주요 파라미터: `LAWD_CD` 법정동코드 앞 5자리, `DEAL_YMD` 계약월 `YYYYMM`
   - 운영 주기: 서울/경기 주요 법정동을 매일 수집하고 최근 월은 더 자주 갱신

2. 주소와 좌표 매핑
   - 입력: 시군구명, 법정동명, 지번, 단지명
   - 처리: `서울 서초구 반포동 1-1`처럼 주소를 정규화한 뒤 Kakao 좌표 검색으로 위경도 변환
   - 저장: 같은 주소는 Firebase에 캐시해 API 호출량 절감

3. 단지 정보 결합
   - API: `국토교통부 건축HUB 건축물대장정보`
   - 후보 엔드포인트: `getBrTitleInfo`, `getBrRecapTitleInfo`
   - 결합 필드: 총 세대수, 주차대수, 용적률, 사용승인연도, 주용도

4. 신뢰 필터링
   - 취소 거래: `cdealType`이 취소로 표시된 건은 기본 노출 제외
   - 직거래: `dealingGbn`이 `직거래`인 건은 제외하지 않고 별도 표시
   - 법인 거래: 매수/매도 주체가 법인인 경우 태그로 표시

## 필요한 키

- 공공데이터포털 서비스키: `국토교통부_아파트 매매 실거래가 자료`
- 공공데이터포털 서비스키: `국토교통부 건축HUB 건축물대장정보`
- Kakao JavaScript 키: 현재 로컬 지도 렌더링에 사용 중
- Kakao REST API 키: 서버에서 대량 주소-좌표 변환을 할 때 선택적으로 사용

## 운영 메모

공공데이터포털 키와 Kakao REST API 키는 브라우저에 넣지 않는다. Firebase Cloud Functions에서 API를 호출하고, Firestore에는 정규화된 거래, 좌표, 단지 상세, 수집 로그만 저장한다.
